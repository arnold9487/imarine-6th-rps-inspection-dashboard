# 動態風險巡檢決策儀表盤(RPS Dashboard)

> 高雄港各貨櫃中心的**即時風險巡檢分數(RPS)**排名 —— 把「港口壅塞壓力(PPI)」與「AI 貨櫃破損偵測」融合成一個決策,回答:**此刻,巡檢人力該先派去哪。**

這是「智慧貨櫃動態風險巡檢決策系統」的**智慧決策層**展示。壓力(PPI)是背景、破損偵測是即時疊加,RPS 是排序鍵。

---

## 怎麼開

- **離線(最保險)**:直接雙擊 `index.html`,用瀏覽器開即可。**完全離線、零依賴、不需 Python 或伺服器。**
- **線上**:部署於 GitHub Pages(靜態網頁)。

整個資料夾可複製到隨身碟或任何電腦,雙擊 `index.html` 就能跑。請保持資料夾一起複製,勿只複製單一檔案。

## RPS 公式

```
RPS = PPI × ( 1 + β · D_score )        β = 0.02

  PPI     = 在泊小船等量 / 泊靠上限        （壅塞：漏檢機率的代理）
  D_score = Σ 在泊貨櫃的破損信心           （破損暴露：該漏的東西有多少）
  小船等量 : 大船 3 / 中船 2 / 小船 1
```

**為什麼相乘不相加**:漏檢損失只有在「櫃是壞的」**且**「忙到漏檢」同時成立時才發生 —— 這是交互作用(AND),數學上即相乘。相加會讓大尺度那一項淹沒另一項,退化成兩個並排系統而非融合。

**為什麼是 (1 + β·D_score)**:沒有破損警報時 RPS 退化為純 PPI(系統仍是可用的壅塞看板);有警報時才做非線性放大。

**β 怎麼定**:β = 1/N,N =「多少預期壞櫃值得讓一個中心的巡檢急迫度加倍」。取 N≈50 → β=0.02。經驗證,巡檢排名在 β ∈ [0.005, 0.2](40 倍範圍)內完全穩定 —— β 改變 RPS 的數值大小,不改變「派誰去」的決策。上線後可用歷史複核紀錄回歸校準。

## 資料來源與誠實聲明

- **壓力(PPI)**:TPNET 全年進出港紀錄(2024-11 ~ 2026-02,8,863 筆)**實算**。
- **破損信心**:YOLO11s 模型(SeaFront 合成資料訓練)對 SeaFront 測試集 **2,480 張**的**真實推論輸出**(damage mAP@50 = 0.80、container = 0.995);共抽出 876 個真實破損信心值。
- **情境模擬**:破損影像為模型真實推論之代表性樣本;到港排程與貨櫃指派為情境模擬 —— 每艘船依船型設 TEU(大 900 / 中 600 / 小 300),破損率 1.5% 決定預期壞櫃數,每壞櫃之信心值自真實推論池隨機抽取。兩個高潮場景之異常批次為刻意編排,但 RPS 由真實 PPI × 真實模型信心即時計算。

## 檔案結構

```
巡檢決策儀表盤/
├─ index.html              主頁(雙擊即開)
├─ css/dashboard.css       樣式
├─ js/dashboard.js         儀表盤邏輯(RPS 計算、時間軸、排名重排動畫)
├─ data/
│  └─ inspections.js       ★ 網頁唯一需要的資料檔(船班 + 指派 + 場景)
└─ build/                  （產資料用,網頁執行時不需要）
   ├─ extract_damage_pool.py   對測試集推論,抽真實破損信心 → damage_pool.json
   └─ build_inspections.js     指派貨櫃+破損、編排場景 → data/inspections.js
```

**部署 GitHub Pages 時,網頁只需**:`index.html`、`css/`、`js/`、`data/inspections.js`。

---

## 重建資料(選用)

```bash
# 1) 抽真實破損信心(需 ultralytics + 測試集,一次性)
python build/extract_damage_pool.py

# 2) 產生指派與場景
node build/build_inspections.js
```
